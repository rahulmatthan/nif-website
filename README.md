# New India Foundation — website

A production static site for the New India Foundation: the Fellowships, the **NIF Book Prize**, and the
Library of every book NIF has produced or honoured. Built with **Hugo Extended**, deployed to **GitHub
Pages** by GitHub Actions on every push to `main`.

**Live:** https://exmachina.in/nif-website/ &nbsp;(served under the account's Pages custom domain; for
NIF's own domain, see *Deploying* below.)

Content editors never touch HTML. Everything on the site is driven by data files in `data/`.

---

## Run it locally

Prerequisites: **Hugo Extended ≥ 0.164** and **Node ≥ 18** (Node is only for the data/asset build scripts).

```bash
# 1. (first time, or when covers change) download images from the CDN and build data/books.yaml
node build/extract.mjs          # regenerates data/books.yaml from the prototype + verified research
node build/fetch-assets.mjs     # downloads covers, board photos, logo into assets/  (skips existing covers)
node build/make-base.mjs        # regenerates the Open Graph card canvas (rarely needed)

# 2. serve with live reload
hugo server

# open http://localhost:1313/nif-website/
```

For a one-off production build: `hugo --gc --minify`. Output lands in `public/`.

> The covers and photos in `assets/` are committed, so a plain `hugo server` works without the Node steps.
> You only need the Node scripts when regenerating `data/books.yaml` or refreshing images.

## How the site is put together

```
data/            ← the entire editable site content
  books.yaml       all 46 books: title, author, route, NIF description, publisher/year/ISBN, reviews, awards
  board.yaml       Governing Board (bios + photos)
  fellows.yaml     fellows by round (book + translation)
  juries.yaml      Book Prize jury
  status.yaml      application status + dates + amounts  ← flips every CTA
  news.yaml        announcements + video series
assets/          ← images (covers/, people/, logo, og/) and css/main.css (the design system)
content/         ← thin front-matter pages; books/_content.gotmpl generates /books/<slug> from books.yaml
layouts/         ← templates (partials/ = header, ribbon, footer, cover, cta, og-card, …)
build/           ← Node helpers: extract.mjs, fetch-assets.mjs, make-base.mjs
.github/workflows/hugo.yml   ← CI: build + deploy to Pages
reference/prototype.html     ← the original single-file prototype (the spec). Not built.
```

The design system (colours, type, components) lives in **`assets/css/main.css`** and is carried across
from the prototype verbatim. Colours are CSS variables in `:root`; don't introduce new ones.

## Common edits

### Add a book (fellowship book or prize winner)
Append an entry to **`data/books.yaml`**. Minimum fields:

```yaml
- slug: "a-unique-slug"          # lowercase, hyphenated; becomes /books/a-unique-slug/
  title: "The Title: Subtitle"
  author: "Author Name"
  route: "prize"                  # "prize" or "fellowship"
  prizeYear: 2026                 # for prize winners; null for fellowship
  round: null                     # for fellowship books: the round number
  joint: false
  translation: false
  theme: "biography"              # politics | biography | caste | environment | gender | culture | economy | region
  publisher: "Publisher"
  year: 2026
  isbn: "978-…"
  cover: ""                       # leave blank; put the image at assets/covers/a-unique-slug.jpg
  buyAmazon: "https://…"
  buyPublisher: "https://…"
  shortDescription: "One line for the Prize page / homepage."
  description: |-
    NIF's own account of the book. Verbatim; do not use publisher blurb.
  reviews: []                     # see below
  awards: []
```

Then drop the cover image at `assets/covers/<slug>.jpg` (any web image; Hugo makes the WebP/srcset).
The Library, filters, homepage strip, related-books and a full `/books/<slug>/` page all update from
this one entry. If `cover` is blank and no file exists, a styled placeholder shows automatically.

> `data/books.yaml` is generated by `build/extract.mjs`, which merges the prototype content with verified
> research. If you re-run that script, hand-edits to `books.yaml` will be overwritten — put durable
> changes into the script's inputs, or stop running the script and edit `books.yaml` directly (it is the
> source of truth for the build either way).

### Add a review to a book
Reviews must come from a real, linkable source (never invented). Under the book's `reviews:`:

```yaml
  reviews:
    - publication: "The Hindu"
      reviewer: "Reviewer Name"      # or "" if unbylined
      date: "March 2021"             # or ""
      quote: "A short verbatim quote, under 25 words."
      url: "https://www.thehindu.com/…"
```

One quote per publication; keep it short; always link out. No reviews → leave `reviews: []` and the page
shows the styled empty state with the press contact.

### Add a winner
Same as adding a book with `route: "prize"` and a `prizeYear`. The homepage shelf, the current-winner
panel and the Book Prize winners list all derive from the prize books, newest first.

### Add a fellow
Edit **`data/fellows.yaml`** — append to a round's `fellows`, or add a new round block.

### Add a news item
Prepend to `items:` in **`data/news.yaml`** (newest first).

### Flip application status (the important one)
Everything about what's open/closed is in **`data/status.yaml`**. For each programme:

- `state: auto` computes open / opening-soon / closed from the `opens` and `closes` dates.
- Force it with `state: open`, `state: closed`, or `state: soon`.
- When a cycle ends, bump the year on `opens`/`closes` (and `cycle`) and the whole site rolls forward.

One edit here updates the status ribbon, every Apply button, the Apply page and the Book Prize page.

### Connect the application form
The Apply page has a real form (proposal / sample chapter / schedule as file uploads). To make it live:

1. Create a form at **Formspree** (a plan that allows file uploads) — or any endpoint that accepts
   `multipart/form-data`.
2. Paste its endpoint into `data/status.yaml → formEndpoint`.

Until then the form shows a notice and points applicants at `fellowships@newindiafoundation.org`.

## Deploying

Pushing to `main` triggers `.github/workflows/hugo.yml`, which builds with Hugo Extended and publishes to
GitHub Pages. Nothing else to do.

`baseURL` is pinned in `hugo.toml` (currently `https://exmachina.in/nif-website/`). The workflow does **not**
override it — GitHub's `configure-pages` reports an `http://`, apex-only URL that drops the `/nif-website`
subpath and breaks internal links, so we ignore it and trust `hugo.toml`.

> **Why internal links must stay relative (no leading slash).** Because the site lives under a subpath,
> templates build links with `relLangURL`/`relURL` using **relative** inputs (`"prize/"`, not `"/prize/"`).
> A leading slash makes Hugo anchor to the host root and drop the `/nif-website/` prefix. When you move to a
> root domain this no longer matters, but keeping links relative is correct in both cases.

**To move to NIF's own domain** (e.g. `www.newindiafoundation.org`):
1. Set `baseURL = "https://www.newindiafoundation.org/"` in `hugo.toml`.
2. Add the domain in the repo's Pages settings (and the DNS records GitHub asks for).
3. The 33 legacy-URL aliases (`/nif`, `/governing-board`, `/book-prize`, …) then resolve at the site root,
   so nothing 404s at cutover.

## The build scripts

| Script | What it does |
|---|---|
| `build/extract.mjs` | Rebuilds `data/books.yaml` from the prototype's content + merges verified research from `build/research/out-*.json`; also writes `REVIEWS-FOUND.md`. |
| `build/fetch-assets.mjs` | Downloads book covers, board photos and the logo from the Squarespace CDN into `assets/`. |
| `build/make-base.mjs` | Regenerates the solid canvas used for Open Graph cards. |
